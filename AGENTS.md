## Reglas de comportamiento (obligatorias)

- Haz SOLO el cambio mínimo necesario para resolver lo que se pide. Nada de "mientras estaba aquí, también...".
- No generes secciones, badges ni enlaces que no se hayan pedido.
- No reordenes ni reescribas el README completo si solo se pide un ajuste puntual.
- Si hay dudas sobre el alcance, pregunta antes de tocar más.

## Contenido

- `README.md`: único archivo del repo; perfil con banner, presentación, stack, proyectos destacados, estadísticas y contacto.
- Proyectos listados: `cocbase-app`, `cocbase-web`, `inge`, `diezmapp`. No incluir `cyberguard`.
- Cada proyecto lleva descripción breve, stack y badges de Código y Demo.

## Convenciones

- Textos del perfil en español; nombres de proyectos y stack como en cada repo.
- El badge de Demo apunta a la URL pública del proyecto; no duplicar enlaces.
- Mantener el orden: presentación → stack → proyectos → estadísticas → contacto.
- No incluir capturas propias en el perfil; se usan badges y banners externos.

## Verificación

- Revisar el README renderizado (banner, badges, enlaces y tablas).
- Comprobar que los enlaces de cada proyecto y su demo responden.

## Git y commits

- Commits pequeños, uno por cambio, solo cuando el usuario lo pida.
- Nunca hacer push, crear ramas ni reescribir el historial sin que se pida.
- Formato: `<tipo>: <descripción breve en inglés, minúsculas, imperativo>`.
